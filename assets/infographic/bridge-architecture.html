Zo Computer · Automation Architecture

The harness owns the loop.
Zo MCP becomes the tool server.

A Zo-hosted automation borrows Claude as a model, so every turn is metered by the platform and dies at the first ceiling it touches. Invert it: let the Claude Code CLI own the agent loop and expose Zo as an MCP tool server. Two bridge scripts make the swap, and the resilience contract moves inside.

The two scripts that make the swap

bridge-launch.sh

The entire Zo instruction body. Checks a PID+starttime file so a still-running job is never doubled, runs an optional preflight that skips the model call when there is no work, extracts the automation ID from the prompt, and execs the runner.

setsid nohup a claude -p that survives the turn. Exports IS_SANDBOX=1 (root cannot skip permissions without it), then reconciles the contract after exit and writes a receipt — because a clean exit with an open contract is ended_mid_contract, not success.
